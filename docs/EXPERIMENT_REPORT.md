# 校园成长护照：实验技术报告

本报告根据运行源码及 38 张截图整理，作为工程技术说明；不是在发布过程中重新执行的链上验收，也不代替组织方指定格式的正式实验报告。

## 目标与方案

选题为校园链上数字资产管理平台：以 FT 表示校园贡献积分，以身份绑定 NFT 表示校园成就，通过任务合约协调任务状态与奖励。应用沿用原 chain1 和三个原合约，不因 GUI 优化重建环境。

原始赛题基础功能覆盖积分发行/转账/查询、徽章颁发/所有权查询、任务创建/领取/审核以及 Web 交互。扩展选择积分消费与成长护照，保持课程实践规模。

## 业务设计

任务状态为 CLAIMED（已领取）、SUBMITTED（待审核）、APPROVED（已完成）、REJECTED（待补充材料）。材料以原始文本或文件字节计算 SHA-256，仅摘要上链。管理员审核后，任务合约通过授权调用 FT/NFT 奖励能力，关联领取记录、审核交易和徽章。

三类贡献分别为技术成长、志愿服务、绿色校园。完成全部三类后可领取一次 30 积分成长奖励；原合约保留去重记录。成长印章只是界面派生展示，不自行产生链上资产。

商城有两个固定商品：星环头像框 20 积分、极光个人背景 35 积分。订单在本地 SQLite 中记录，支付使用原 FT Transfer，回查验证链、合约、方法、订单编号、付款人、接收人、金额、执行结果与区块高度后确认权益。支付超时不自动再次扣款。

## 结果口径

商城阶段：Alice 125、Bob 60、校园兑换账户 55，余额总和 240，与发行量一致；兑换是积分转移，不是销毁。徽章仍为 3。恢复默认只删除当前用户外观偏好，保留已支付订单。

新增 V10 模板直接使用原快照数据。任务和徽章状态没有可靠事件时间，因此展示状态摘要而非虚构时间轴。首页仅承载概览与入口，完整操作保留在对应业务视图。

## 创新与局限

将校园贡献、审核、奖励、成就和消费连接为可核查闭环，并把装扮所有权和外观偏好分离。展示层使用真实持有徽章和任务状态，避免用浏览器存储伪造资产。

当前没有新增商城合约，没有使用 IPFS/ZKP，没有实现完整 Joi 体系，也不具备完整历史累计收支或学期时间轴。正式生产部署还需处理稳定会话密钥、生产服务配置、异常脱敏、链下订单备份和更完整的并发/故障测试。
